# Замер VLM перед тем, как её принять

## Главное правило

**Мерить детекцию, а не скорость.** На этом железе `gemma-4-12b-qat` не просто
медленнее (~25 с/кадр против ~3 с у `qwen3-vl-8b`) — она НЕ ВИДИТ дефект вообще:
0 из 9 на кадрах, где 8B-модель даёт 9 из 9. Один только замер latency привёл бы
к выбору модели, которая молчит.

Второй по важности вывод: **промпт решает больше, чем модель.** Переписанный
системный промпт поднял recall с 5/9 до 9/9 на той же модели за то же время.

## Порядок действий

### 1. Поднять сервер и посмотреть, что установлено

```bash
lms server start
lms ls --json        # поле vision:true показывает мультимодальные модели
lms runtime ls       # на NVIDIA должен быть выбран ...nvidia-cuda12-avx2
lms ps               # что загружено и сколько занимает
nvidia-smi --query-gpu=memory.used,memory.total --format=csv
```

Модель загружается автоматически при первом запросе с её именем (JIT), но
переключение между моделями удобнее делать явно:

```bash
lms unload --all && lms load qwen/qwen3-vl-8b --gpu max --context-length 8192
```

### 2. Замерить

```bash
python .claude/skills/vlm-bench/bench.py qwen/qwen3-vl-8b
python .claude/skills/vlm-bench/bench.py google/gemma-4-12b-qat
```

Скрипт берёт кадры демо-видео по манифесту (дефектные и чистые), прогоняет через
`src/analyzer.py` и печатает recall, попадание рамки, ложные срабатывания и время.

### 3. Что смотреть в результатах

| Метрика | Почему важна |
|---|---|
| recall на дефектных | молчащая модель бесполезна, даже если быстрая |
| ложные на чистых | «испорчено» на фартуке хуже пропуска |
| попадание рамки | у VLM обычно плохое — геометрию даёт `src/box_refine.py` |
| время на кадр | определяет, живой это режим или пакетный |
| VRAM | 12B на 8 ГБ забивает память целиком (7972/8192 МБ) и тормозит |

## Подводные камни LM Studio

- `chat_template_kwargs.enable_thinking: false` уважают не все модели: gemma всё
  равно возвращает рассуждения в `reasoning_content`. Дублируй с
  `reasoning_effort: low` и жёсткой JSON-схемой в `response_format`.
- Пустой `content` при непустом `reasoning_content` — модель положила ответ туда,
  разбирать надо оба поля (в `analyzer.py` это уже учтено).
- Повышать разрешение входа бесполезно: 1024px вместо сквоша 448 дал втрое больше
  времени и вчетверо больше ложных срабатываний.
