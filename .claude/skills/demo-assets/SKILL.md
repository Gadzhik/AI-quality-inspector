# Пересборка демо-ассетов

## Главное правило

**Ассеты рендерятся из конвейера, а не снимаются с экрана.** Запись экрана
приносит рамку окна и панель задач, весит втрое больше, и любой баг в ней
застывает навсегда. Так в проект едва не попал ролик, где красная рамка тревоги
подписана «НЕТ ОБРАЗЦА 95%».

## Команды

### Демо-ролик (обученная модель на видео цеха)

```bash
python main_freshness.py --source production.mp4 --limit 900 --record _demo_raw.mp4
```

Затем сжать в H.264 — `cv2.VideoWriter` пишет mp4v, который весит вчетверо больше:

```bash
ffmpeg -y -i _demo_raw.mp4 -c:v libx264 -crf 26 -preset slow \
       -pix_fmt yuv420p -movflags +faststart assets/demo.mp4
```

Ориентир: 900 кадров (36 с) при 1280px → ~24 МБ mp4v → **~6.7 МБ H.264**.

### Скриншот и превью демо-режима (синтетические дефекты)

```bash
python make_preview.py          # -> assets/screenshot.jpg и _preview_raw.mp4
python verify_hud.py            # -> _verify_defect.png, _verify_clean.png
```

Границы кадров и имя модели берутся из манифеста и `DEFAULT_MODEL` — хардкодить
их обратно не надо.

## Проверка перед коммитом

1. Прочитать получившиеся кадры (`Read`) — не полагаться на то, что «должно быть
   нормально». Так были найдены и мисматч подписи тревоги, и статус
   «МЯСО НЕ НАЙДЕНО» при нарисованных рамках `MEAT`.
2. Проверить, что в кадре нет противоречий: подпись тревоги соответствует её
   причине, статус-чип не говорит «QUALITY OK», когда анализа не было.
3. Размер: ролик в репозитории должен оставаться в пределах ~10 МБ.

## Что лежит в git

Только `assets/demo.mp4` и `assets/screenshot.jpg`. Правило в `.gitignore`:
`*.mp4` с исключением `!assets/*.mp4`, поэтому рабочие видео (`production.mp4`,
записи экрана, `_demo_raw.mp4`) в репозиторий не попадут.
