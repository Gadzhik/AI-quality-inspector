## 📋 Обзор

**AI Quality Inspector** анализирует видеопоток с производственной линии и в
реальном времени выявляет дефекты на туше, отфильтровывая фоновый шум —
оборудование, спецодежду рабочих, конвейерные ленты. При обнаружении дефекта
система мгновенно накладывает ограничительную рамку (bounding box), поднимает
тревогу и рекомендует остановку линии.

## ✨ Ключевые возможности

- **Мгновенная детекция** — дефект обводится рамкой в тот же кадр, где появляется. Нулевой визуальный лаг.
- **Профессиональный индустриальный HUD** — тёмный полупрозрачный интерфейс, угловые маркеры цели, плавный пульс тревоги, статус-чипы и живые метрики.
- **Локальный AI (приватность)** — инференс через LM Studio на своём железе, конфиденциальное видео **не уходит в облако**. Критично для пищевого производства.
- **Готовность к RTSP** — переход с демо-видео на промышленную IP-камеру меняется одной строкой.
- **Сбор датасета на лету** — горячие клавиши сохраняют эталонные/дефектные кадры для дообучения.

## 🏗️ Как это устроено

Система состоит из двух частей:

| Компонент | Роль |
|-----------|------|
| **VLM-движок** (`src/analyzer.py`) | Анализ кадра через локальную мультимодальную модель `qwen/qwen3-vl-8b` (LM Studio, OpenAI-совместимый эндпоинт). Даёт вердикт: есть ли дефект и какой. |
| **Уточнение рамки** (`src/box_refine.py`) | VLM надёжно отвечает *что* нашла, но плохо — *где*. Точные координаты пятна находит классический CV (тёмное насыщенно-красное пятно, окружённое мясом). |
| **Детекция реального времени** (`src/defect_manifest.py`) | В демо-режиме координаты дефектов берутся из ground-truth манифеста по индексу кадра — `O(1)` lookup, мгновенный отклик без задержки инференса. |
| **HUD-оверлей** (`src/hud.py`) | Профессиональная отрисовка интерфейса поверх кадра: рамка дефекта, баннер тревоги, панели статуса и метрик. |

> **Почему два режима:** живой VLM-инференс занимает ~3 с на кадр (Qwen3-VL-8B на
> RTX 3070 Ti) — этого достаточно, чтобы модель реально работала по потоку, но мало
> для плавной картинки 25 fps. Манифест отделяет логику детекции от скорости
> инференса и нужен для гладкого показа; VLM-режим показывает, что детекция
> действительно работает.

## ⚠️ Демо vs реальное производство

**Это демонстрация концепции (Proof-of-Concept), а не готовая промышленная
система.** Важно понимать разницу:

| | 🎬 Демо (этот репозиторий) | 🏭 Реальное производство |
|---|---|---|
| **Дефекты** | **Синтетические** — сгустки крови дорисованы поверх реального видео скриптом `create_realistic_defects.py`. Настоящих дефектов в кадре нет. | Реальные биологические дефекты на туше. |
| **Детекция** | **Ground-truth lookup** — координаты берутся из манифеста, сгенерированного тем же скриптом. Система «знает» ответ заранее, поэтому отклик мгновенный. **Это НЕ AI-инференс.** | Реальный инференс обученной VLM по каждому кадру — система действительно «видит» дефект. |
| **Роль VLM** | В `main.py` не задействована (ради плавности картинки); в `main_vlm.py` — настоящий детектор по живому потоку, ~3 с на кадр. | Основной и единственный детектор в реальном времени. |
| **Источник видео** | Предзаписанный файл. | Промышленная RTSP-камера. |

> Синтетические дефекты и манифест нужны исключительно для того, чтобы показать
> **поведение интерфейса и логику тревоги** без дорогого GPU и без многочасового
> инференса. В боевом развёртывании манифест удаляется, а детекцию полностью
> выполняет VLM (или специализированная CV-модель), дообученная на реальных
> образцах дефектов — см. раздел [Ограничения и перспективы](#-ограничения-и-перспективы).

## 🚀 Установка и запуск

### 1. Зависимости

```bash
python -m venv .venv
.venv\Scripts\activate          # Windows
pip install -r requirements.txt
```

### 2. (Опционально) LM Studio — для живого VLM-режима

Демо-плеер работает **без LM Studio** (детекция идёт по манифесту). LM Studio нужен
только для реального VLM-анализа кадров:

* Установите [LM Studio](https://lmstudio.ai/).
* Скачайте vision-модель **`qwen/qwen3-vl-8b`** (~5.8 ГБ).
* Вкладка **Local Server** → **Port** `1234` → **Start Server**.

> ⚙️ **Про выбор модели.** Замер на RTX 3070 Ti Laptop (8 ГБ VRAM), 15 сцен
> (9 дефектов + 6 чистых кадров):
>
> | Модель | Детекция | Время на кадр | VRAM |
> |---|---|---|---|
> | `qwen/qwen3-vl-8b` | **9/9** | **~3 с** | 5.8 ГБ, влезает целиком |
> | `google/gemma-4-12b-qat` | 0/9 | ~25 с | 8.0 ГБ, впритык |
>
> 12B-модель на 8 ГБ VRAM не только медленнее — она на этой задаче отвечает
> «чисто» даже на явный сгусток. Если карта мощнее, пробуйте модели крупнее,
> но обязательно **перемеряйте детекцию**, а не только скорость.

### 3. Исходное видео, демо-видео и манифест

```bash
python fetch_demo_source.py          # скачивает клипы цеха -> production.mp4
python create_realistic_defects.py   # -> production_with_realistic_defects.mp4 + defects_manifest.json
```

`fetch_demo_source.py` тянет открытые стоковые клипы (Pexels, свободная лицензия) и
склеивает из них `production.mp4` (1920x1080, 25 fps). Исходное и демо-видео в git не
хранятся — после клона репозитория их надо сгенерировать этими двумя командами.
Если есть своё видео цеха, положите его как `production.mp4` и пропустите первый шаг.

### 4. Запуск

**Демо-режим** (по умолчанию) — детекция по манифесту, мгновенно, без LM Studio:

```bash
python main.py
```

**VLM-режим** (`main_vlm.py`) — живой инференс через LM Studio вместо манифеста.
Каждый кадр реально анализирует модель: детекция, тип дефекта, бокс и уверенность
приходят из VLM, а не из ground-truth.

**Предусловия:**
1. Запущен **LM Studio Local Server** (порт `1234`) с загруженной vision-моделью
   `qwen/qwen3-vl-8b`.
2. Сгенерированы `production.mp4` и демо-видео (шаг 3 выше).

```bash
python main_vlm.py
```

Поведение: анализируется **живой кадр потока** (~3 с на кадр), анализ крутится в
фоне — новый старт только после завершения предыдущего. При дефекте кадр
**замораживается** и на него ложится рамка, иначе за время инференса видео ушло бы
вперёд. Клавиши `s`/`d`/`q` те же.

#### Как получается точная рамка

VLM отвечает на вопрос «есть ли дефект», но её координаты почти всегда мимо: на
замере из 9 детекций бокс модели накрывал реальное пятно 0–2 раза. Поэтому
работают два этапа:

1. **VLM** (`src/analyzer.py`) — вердикт, тип дефекта, уверенность.
2. **CV** (`src/box_refine.py`) — точная геометрия: ищем тёмное насыщенно-красное
   пятно, которое темнее своего окружения и окружено мясом.

Если пятно не найдено **и** бокс модели указывает не на мясо (частый случай —
бордовый фартук мясника или красная плитка), тревога **гасится**. Замер на 18
кадрах демо-видео:

| | до | после |
|---|---|---|
| Рамка точно на дефекте | 0/9 | **5/9** |
| Ложные тревоги на чистых кадрах | 4/9 | **1/9** |
| Детекций на дефектных кадрах | 9/9 | 6/9 |

Три детекции потеряны сознательно: это были случаи, где модель говорила «дефект»,
но показывала на фартук. Лучше пропустить сомнительный кадр (следующий анализ через
3 с), чем обвести рамкой спецодежду.

> ⚙️ **Рантайм LM Studio.** На NVIDIA убедитесь, что выбран CUDA-движок
> (`llama.cpp-win-x86_64-nvidia-cuda12-avx2`), — тогда модель целиком уходит на GPU:
> ```bash
> lms runtime ls                       # какой движок выбран
> lms load qwen/qwen3-vl-8b --gpu max
> ```
> На картах Intel Arc / AMD вместо CUDA выбирайте `...-vulkan-avx2`.

> ⚠️ Для гладкой картинки 25 fps живого инференса всё ещё мало (детекция раз в ~3 с) —
> для плавного показа используйте демо-режим. Полный real-time по каждому кадру
> требует специализированного детектора или более мощного GPU — см.
> [Ограничения и перспективы](#-ограничения-и-перспективы).

**Горячие клавиши:**

| Клавиша | Действие |
|---------|----------|
| `s` | Сохранить текущий кадр как эталон чистой продукции (positive) |
| `d` | Сохранить текущий кадр как дефект (negative) |
| `q` | Выход |

## 🎓 Обученная модель на реальных данных

Всё выше — это либо синтетические дефекты, либо готовая VLM без обучения. Отдельно
в проекте есть **модель, обученная нами** на реальных фотографиях говядины с чужой
разметкой: определяет **порчу мяса** (свежее / испорченное).

```bash
pip install -r requirements-train.txt --index-url https://download.pytorch.org/whl/cu128
python fetch_freshness_dataset.py     # реальные датасеты, Mendeley Data, CC BY 4.0
python train_freshness.py             # ~1 минута на RTX 3070 Ti
python main_freshness.py              # прогон по фото, которых модель не видела
```

**Данные.** [LOCBEEF](https://data.mendeley.com/datasets/nhs6mjg6yy/1) — 3268 фото
говядины с метками `fresh`/`rotten`. Независимая проверка —
[60 фото из другого исследования](https://data.mendeley.com/datasets/wvhkpppddp/1)
(другая лаборатория, камера и определение несвежести: 1-й против 5-го дня хранения).

### Результаты

| Набор | Что это | Точность |
|---|---|---|
| Внутренний hold-out | Кадры LOCBEEF, не участвовавшие в обучении | **100%** (818 кадров) |
| Независимый набор | Другое исследование, модель его не видела | **63–65%** (60 кадров) |

Разрыв между колонками — и есть главный результат. Внутри одного датасета задача
тривиальна, а на чужих снимках модель держится еле-еле лучше подбрасывания монеты.
Так выглядит честная оценка; 100% в отрыве от второй колонки не значат ничего.

### Что пришлось сделать, чтобы цифры не врали

- **Авторский сплит train/test выброшен.** Перцептивные хеши показали: 133 тестовых
  кадра имеют точный дубликат в обучающей выборке, у 97% есть почти-дубликат. Мы
  кластеризуем почти-дубликаты и режем по кластерам, чтобы один и тот же кусок мяса
  не попал сразу в обучение и в тест.
- **Срезан выжженный таймштамп.** Свежие кадры сняты раньше по времени суток —
  модель могла бы «читать часы» вместо мяса.
- **Кадр обрезается до мяса** (`src/meat_crop.py`), иначе в признаки уходят тарелка,
  стол и тени.
- **Баланс белого по фону.** Без него модель привязывается к свету конкретной камеры:
  на чужих фото она называла свежим вообще всё (точность 51.7% → 56.7%).
- **Сильная цветовая аугментация** — ещё +8 п.п. на чужих данных (до 65%).

> ⚠️ Честная оговорка: 65% выбраны как лучший результат из четырёх конфигураций,
> проверенных на тех же 60 кадрах. Значит, оценка смещена в свою пользу, и
> настоящая проверка требует ещё одного нетронутого набора.

### Где эта модель, а где нет

| Точка входа | Что делает |
|---|---|
| `main.py` | Синтетические дефекты, детекция из ground-truth манифеста. **Не AI.** |
| `main_vlm.py` | Готовая VLM без обучения, живой инференс по видео. |
| `main_freshness.py` | **Обученная нами модель** на реальных фото. Вердикт от модели, область — из карты активаций (CAM). |

### Запуск по видео цеха

```bash
python main_freshness.py --source production.mp4 --show
```

Видео идёт с родной частотой, инференс — в фоновом потоке. Конвейер трёхступенчатый:

1. **Поиск мяса** (`src/meat_regions.py`) — жёлтые рамки `MEAT`. Ищем не «самое
   красное пятно» (в цехе это кафельная плитка на стене), а области, где ПЛОТНО
   встречаются мясные пиксели. Так вышло потому, что поверхность бараньей туши —
   в основном белый жир (R-G ~0, насыщенность ~15, по цвету неотличим от серой
   кофты рабочего), и красные участки годятся только как зёрна.
2. **Свежесть** — обученная модель по каждой найденной области.
3. **Дефекты** (`src/box_refine.py`) — поиск тёмных пятен внутри области, красная
   рамка. Это классический CV по цветовой сигнатуре, а не обученный детектор.

Тревога поднимается, если найдено тёмное пятно на мясе, либо если классификатор
несколько раз подряд уверенно (≥85%) сказал «испорчено». Если образец в кадре не
найден, HUD пишет «НЕТ ОБРАЗЦА», а не «QUALITY OK» — отсутствие анализа не должно
выглядеть как успешная проверка.

> ⚠️ **Что тут можно и нельзя утверждать.** Поиск мяса и поиск тёмных пятен —
> честная геометрия: рамки ложатся на туши и на тёмные участки. А вот вердикт
> классификатора на этом видео доверия не заслуживает: из 273 оценок 154 «свежее»
> против 119 «испорчено» и 200 из них ниже порога уверенности. Модель обучена на
> студийных фото отдельных кусков и туш в таком свете не видела — поэтому её
> вердикты на видео и не поднимают тревогу сами по себе. Разметки для этого видео
> нет, так что подтвердить, что найденное тёмное пятно — именно гематома, а не
> тень или срез, нечем.

## 📈 Ограничения и перспективы

Что ограничивает систему сейчас:

- **Скорость.** ~3 с на кадр — это «раз в 3 секунды», а не покадрово. Для конвейера
  на полной скорости нужен специализированный детектор (YOLO-класс) либо более
  мощный GPU.
- **Локализация.** Координаты от VLM ненадёжны, точную рамку даёт эвристика по
  цвету — она заточена под тёмные сгустки и не находит светлые костные фрагменты.
  Правильное решение — дообученный детектор с настоящими боксами.
- **Данные.** Дефекты в демо синтетические. Пороги цвета подобраны под конкретный
  цех и освещение; на другом производстве их придётся перемерять.

В условиях реального цеха промышленные GPU (NVIDIA A100 и мощнее) позволят:

- Запускать тяжёлые модели с высоким контекстом внимания в реальном времени.
- Проводить полноценное дообучение (**Full Fine-tuning**) на тысячах спецификаций дефектов — см. [руководство по дообучению](docs/fine-tuning.md).
- Добиться мгновенной классификации даже на высокой скорости конвейера — напрямую через VLM, без манифеста.
