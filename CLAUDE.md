# CLAUDE.md — AI Quality Inspector (cross-OS)

Авто-загружается Claude Code в ЛЮБОЙ ОС в этом репозитории. Точка входа для
кросс-ОС преемственности (Windows ↔ Kubuntu). Личная авто-память Claude привязана
к пути и НЕ переносится между ОС. Состояние проекта живёт В РЕПО — в
`PROJECT_STATE.md`.

## ⚠️ Правило преемственности (читать первым делом)

1. В начале сессии прочитай **`PROJECT_STATE.md`** — живой журнал статуса.
2. Дополняй его записями с датой (не переписывай). Обе ОС пишут в один файл.
3. Преемственность через git — незакоммиченное на другую ОС не перейдёт.

## Что за проект

**AI-контроль качества мяса**: детекция дефектов на видеопотоке производственной
линии с профессиональным HUD-оверлеем. Proof-of-Concept, весь инференс локальный
(приватность, видео не уходит в облако). Python 3.10+ (проверено на 3.14), OpenCV.

## Три разных режима — не путать их между собой

Это главный источник недоразумений в проекте. У каждой точки входа своя честность:

| Точка входа | Что реально происходит |
|---|---|
| `main.py` | Синтетические дефекты, нарисованные скриптом; детекция = `O(1)` lookup из ground-truth манифеста по номеру кадра. **Это не AI**, это витрина интерфейса. |
| `main_vlm.py` | Живой инференс готовой VLM `qwen/qwen3-vl-8b` через LM Studio по живому кадру. Вердикт настоящий, обучения не было. Геометрию рамки даёт CV (`src/box_refine.py`), а не модель. |
| `main_freshness.py` | Модель, **обученная нами** (`train_freshness.py`) на реальных размеченных фото. Поиск мясных областей → свежесть по каждой → поиск тёмных пятен. |

**Никогда не выдавать одно за другое** — ни в README, ни в ответах, ни в HUD.

## Архитектура

```
src/
  analyzer.py       VLM-движок (LM Studio, DEFAULT_MODEL = qwen/qwen3-vl-8b)
  box_refine.py     уточнение рамки дефекта по цветовой сигнатуре + предохранители
  camera.py         захват видео (файл / RTSP)
  defect_manifest.py  ground-truth детекция для демо-режима
  freshness.py      инференс обученного классификатора + локализация через CAM
  meat_crop.py      маска мяса, баланс белого, кроп (ОБЩИЙ код обучения и инференса)
  meat_regions.py   поиск областей мяса в сцене цеха
  hud.py            HUD-оверлей
```

Скрипты: `fetch_demo_source.py` (качает исходное видео), `create_realistic_defects.py`
(генератор демо), `fetch_freshness_dataset.py` + `train_freshness.py` (данные и
обучение), `verify_hud.py`, `make_preview.py`, `prepare_training_json.py`.

## Рабочие правила, выведенные из ошибок

Каждое из них уже было нарушено и стоило времени:

- **Препроцессинг обучения и инференса — один и тот же код.** Расхождение в
  ресемплинге (PIL/bilinear против cv2/INTER_AREA) стоило 5 п.п. точности.
  Поэтому `src/meat_crop.py` общий, а `meat_bbox` нельзя менять «под сцену» —
  для сцен есть отдельный `meat_regions.py`.
- **Пороги — из замера, а не из головы.** Навык `calibrate-thresholds`.
- **Метрике на чужом сплите не верить, пока не проверена утечка.** Навык
  `dataset-audit`.
- **Модель выбирать по детекции, а не по скорости.** Навык `vlm-bench`.
- **Классификатор не умеет воздерживаться** — «не знаю» добавляется снаружи
  (`looks_like_meat`, порог уверенности, накопление вердиктов).
- **HUD не должен показывать «QUALITY OK», когда анализа не было.** Для этого у
  `hud.render` есть параметр `status`.
- **Демо-ассеты рендерятся из конвейера, не снимаются с экрана.** Навык
  `demo-assets`.
- Аддитивность, документация и комментарии на русском. Ветка по умолчанию — `main`.

## Навыки проекта (`.claude/skills/`)

| Навык | Когда |
|---|---|
| `dataset-audit` | перед обучением на чужих данных и при подозрительно высокой точности |
| `calibrate-thresholds` | перед написанием любого цветового порога, при новом видео/освещении |
| `vlm-bench` | при выборе или смене модели, при правке системного промпта |
| `demo-assets` | после любой правки, влияющей на картинку |

## Окружение

| | Windows (текущая) | Kubuntu |
|---|---|---|
| Python | 3.14 в `.venv` | python3 3.10+, свой `venv` |
| Демо-зависимости | `pip install -r requirements.txt` | то же |
| Обучение | `pip install -r requirements-train.txt --index-url https://download.pytorch.org/whl/cu128` | подобрать индекс под свою CUDA |
| GPU | NVIDIA 8 ГБ VRAM, torch видит CUDA | проверить `torch.cuda.is_available()` |
| Инференс VLM | LM Studio, рантайм `...nvidia-cuda12-avx2` | LM Studio для Linux, тот же эндпоинт |

Совет из старых версий README про Vulkan актуален только для Intel Arc / AMD;
на NVIDIA нужен CUDA-рантайм.

Не переносятся между ОС и не коммитятся: `.venv/`, `data/`, `models/*.pt`,
`_source_clips/`, любые `*.mp4` кроме `assets/demo.mp4`, выходные кадры.
После клона: пересоздать venv, затем `fetch_demo_source.py` →
`create_realistic_defects.py`, при необходимости `fetch_freshness_dataset.py` →
`train_freshness.py`.

## Что нельзя утверждать про эту систему

- Что она детектирует настоящие сгустки крови: обучающих данных с реальными
  сгустками в открытом доступе нет, обученная модель различает свежесть/порчу.
- Что тёмное пятно на видео — гематома: это находка цветовой эвристики,
  разметки для видео нет.
- Что 100% на hold-out что-то значат в отрыве от 65% на независимом наборе.

Полная история и текущий фронт — в **`PROJECT_STATE.md`**.
