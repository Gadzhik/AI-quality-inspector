# CLAUDE.md — AI Quality Inspector (cross-OS)

Авто-загружается Claude Code в ЛЮБОЙ ОС в этом репозитории. Точка входа для
кросс-ОС преемственности (Windows ↔ Kubuntu). Личная авто-память Claude
(`~/.claude/.../memory`) привязана к пути и НЕ переносится между ОС. Состояние
проекта живёт В РЕПО — в `PROJECT_STATE.md`.

## ⚠️ Правило преемственности (читать первым делом)

1. В начале сессии прочитай **`PROJECT_STATE.md`** — живой журнал статуса.
2. Дополняй его записями с датой (не переписывай). Обе ОС пишут в один файл.
3. Преемственность через git — незакоммиченное на другую ОС не перейдёт.

## Что за проект

**AI-контроль качества мяса** в реальном времени: детекция биологических дефектов
(сгустки крови, гематомы, костные фрагменты) на видеопотоке производственной линии,
с профессиональным HUD-оверлеем. **Proof-of-Concept**, локальный инференс через
**LM Studio** (приватность, видео не уходит в облако). Python 3.10+, OpenCV.

Архитектура (см. README → «Как это устроено»):
- `src/analyzer.py` — VLM-движок, модель `google/gemma-4-12b-qat` через LM Studio
  (OpenAI-совместимый эндпоинт). Для R&D/валидации. ~45–75 с на кадр на дом. железе.
- `src/defect_manifest.py` — детекция реального времени: в демо координаты дефектов
  берутся из ground-truth манифеста (`defects_manifest.json`) по индексу кадра,
  O(1) lookup, мгновенно (отделяет логику детекции от скорости инференса).
- `src/hud.py` — отрисовка HUD поверх кадра.

Точки входа: `main.py` (демо-плеер), `main_vlm.py` (live VLM-режим с manifest-guided
сэмплингом). Утилиты: `create_*defects.py`, `prepare_training_json.py`, `verify_hud.py`,
`mock_innova.py`. Дообучение — в `docs/`.

> ⚠️ **Демо vs прод:** в демо дефекты синтетические (наложены), детекция в
> демо-режиме идёт из манифеста, НЕ реальным AI. На промышленном GPU тот же
> конвейер работает целиком на VLM. Не выдавать демо за реальную детекцию.

## Кросс-ОС: тулчейн и пути

| | Windows (текущая) | Kubuntu |
|---|---|---|
| Корень | `C:\ai_dev\agriko_antigrav_quality_inspector` | где склонирован (Claude ИМЕННО там) |

| Зависимости | `requirements.txt` | `python3 -m venv venv && pip install -r requirements.txt` |
| Инференс | LM Studio (локальный сервер) | LM Studio для Linux, тот же OpenAI-совместимый эндпоинт |
| GPU | (Vulkan ускорение упоминается в README) | проверить доступность GPU/Vulkan |

`venv/`, `__pycache__/`, большие `*.mp4`, выходные кадры (`detected_defects/`,
`_defect_frames/`) — ОС-/прогон-специфичны, в репо коммитить осторожно. После клона
на Kubuntu пересоздать venv (Windows venv не переносится).

## Рабочие правила

- LM Studio должен быть запущен с нужной моделью, иначе VLM-режим не работает —
  endpoint в конфиге проекта.
- Аддитивность, доки на русском. Ветка по умолчанию — `main`.
- Не выдавать синтетическое демо за реальную детекцию (см. дисклеймер выше).
